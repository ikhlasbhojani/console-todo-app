# Data Model: TODO APP - SQLITE (PHASE 1)

**Feature Branch**: `001-todo-sqlite`
**Date**: 2025-12-04
**Status**: Complete

## Overview

This document defines the data model for the console-based todo application. Phase 1 includes a single entity (Task) with SQLite persistence.

---

## Entities

### Task

Represents a single todo item that a user wants to track.

#### Attributes

| Attribute | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| id | int | Yes (auto) | AUTO | Unique identifier, auto-generated by SQLite |
| title | str | Yes | - | Short description of the task (1-100 chars) |
| description | str | No | "" | Optional detailed description |
| status | str | Yes | "pending" | Current state: "pending" or "done" |
| created_at | datetime | Yes (auto) | NOW | Timestamp when task was created |
| updated_at | datetime | Yes (auto) | NOW | Timestamp when task was last modified |

#### Validation Rules

| Rule | Attribute | Constraint |
|------|-----------|------------|
| V1 | title | Cannot be empty or whitespace-only |
| V2 | title | Maximum 100 characters (display truncated at 17) |
| V3 | status | Must be exactly "pending" or "done" |
| V4 | id | Must be positive integer |

#### State Transitions

```
[NEW] --add--> [pending] --complete--> [done]
                   ^                      |
                   |______uncomplete*_____|

* uncomplete not in Phase 1 scope
```

#### Python Dataclass Definition

```python
from dataclasses import dataclass
from datetime import datetime

@dataclass
class Task:
    """Represents a single todo task.

    Attributes:
        id: Unique identifier (auto-generated by database)
        title: Short description of what needs to be done
        description: Optional longer description with details
        status: Current state - either "pending" or "done"
        created_at: When the task was first created
        updated_at: When the task was last modified
    """
    id: int
    title: str
    description: str
    status: str  # Literal["pending", "done"]
    created_at: datetime
    updated_at: datetime

    @classmethod
    def from_row(cls, row: sqlite3.Row) -> "Task":
        """Create a Task from a database row."""
        return cls(
            id=row["id"],
            title=row["title"],
            description=row["description"],
            status=row["status"],
            created_at=datetime.fromisoformat(row["created_at"]),
            updated_at=datetime.fromisoformat(row["updated_at"]),
        )

    def is_completed(self) -> bool:
        """Check if task is marked as done."""
        return self.status == "done"

    def format_status(self) -> str:
        """Format status for display: '[ ] Pending' or '[x] Done'."""
        if self.status == "done":
            return "[x] Done"
        return "[ ] Pending"

    def format_date(self) -> str:
        """Format created_at for display: 'YYYY-MM-DD HH:MM'."""
        return self.created_at.strftime("%Y-%m-%d %H:%M")
```

## Database Schema

### SQLite Table: tasks

```sql
-- Create tasks table if it doesn't exist
CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    status TEXT DEFAULT 'pending' CHECK(status IN ('pending', 'done')),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

-- Index for common queries (optional, for future scale)
CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status);
```

### Column Details

| Column | SQLite Type | Constraints | Notes |
|--------|-------------|-------------|-------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | Never reused after deletion |
| title | TEXT | NOT NULL | User-provided task title |
| description | TEXT | DEFAULT '' | Empty string if not provided |
| status | TEXT | DEFAULT 'pending', CHECK | Enforced at DB level |
| created_at | TEXT | NOT NULL | ISO 8601 format |
| updated_at | TEXT | NOT NULL | ISO 8601 format |

## CRUD Operations Mapping

| Operation | SQL Statement | Returns |
|-----------|--------------|---------|
| Create | `INSERT INTO tasks (...) VALUES (...)` | New Task with generated ID |
| Read All | `SELECT * FROM tasks ORDER BY id` | List[Task] |
| Read One | `SELECT * FROM tasks WHERE id = ?` | Task or None |
| Update | `UPDATE tasks SET ... WHERE id = ?` | bool (success) |
| Delete | `DELETE FROM tasks WHERE id = ?` | bool (success) |

### SQL Templates

```sql
-- Add task
INSERT INTO tasks (title, description, status, created_at, updated_at)
VALUES (?, ?, 'pending', ?, ?);

-- List all tasks
SELECT * FROM tasks ORDER BY id;

-- Get single task
SELECT * FROM tasks WHERE id = ?;

-- Update task (title and/or description)
UPDATE tasks SET title = ?, description = ?, updated_at = ? WHERE id = ?;

-- Complete task
UPDATE tasks SET status = 'done', updated_at = ? WHERE id = ?;

-- Delete task
DELETE FROM tasks WHERE id = ?;
```

## Data Integrity

### Invariants

1. Every task has a unique positive integer ID
2. Every task has a non-empty title
3. Status is always exactly "pending" or "done"
4. created_at is set once and never changes
5. updated_at is updated on every modification (including status change)

### Concurrency

- Single-user application: no concurrent access concerns
- Per-operation database connections: no lock contention
- Transactions via context manager ensure atomic operations
